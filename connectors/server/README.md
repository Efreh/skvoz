# Серверный коннектор SKVOZ

`skvoz-server` передаёт TCP-трафик к назначениям через существующие универсальное
ядро Core и NATS. Текущая реализация использует Ruby 4.0.7 и управляет тем же
`skvoz-core-daemon` 1.4.0. Маршрутизация NATS, учёт кредита, состояния потоков
и кодирование пакетов остаются в ядре; Ruby управляет сокетами назначения,
выдачей учётных данных, TLS и процессами.

[Руководство сервера](../../docs/server-connector.md) содержит основной контракт
развёртывания, конфигурации, метаданных, идентификаторов и проверок.
В нём описаны запуск готового образа из GHCR через Compose и локальная сборка
того же Dockerfile из исходников. Подпроект хранит собственные
Gemfile/lock-файл, исходники, исполняемую команду, Dockerfile, файлы Compose,
тесты RSpec.

Для сборки и запуска сервера достаточно Docker/Compose. Ruby 4.0.7, gems,
скомпилированный демон ядра и NATS входят в один образ на Ruby Bookworm.
Один Dockerfile содержит этапы `base`, `tests` и `deploy`, а также сборку ядра
и получение бинарника NATS. CI запускает `tests` и публикует `deploy`;
локальный Compose собирает тот же `deploy`.
Генерация конфигурации, сертификаты, учётные данные
и управление NATS/демоном ядра выполняются самим Ruby-коннектором при запуске.

Команды и зависимости регрессионных проверок находятся в
[разделе проверок руководства](../../docs/server-connector.md#регрессионные-проверки).
CI запускает RSpec с настоящими бинарниками ядра, NATS и тестового центра ACME,
а также настоящий контейнер через Compose: с готовым образом и с локальной сборкой.
Этап `tests` получает Pebble 2.10.1 из официального образа с зафиксированным digest.
Тестовые зависимости входят только в этот этап. Проверки коннектора используют Ruby/RSpec.
Состояние и учётные данные проверок создаются во временных каталогах.

Сервер передаёт байты TCP. Клиентские интерфейсы HTTP/SOCKS, настольный UI
и автоматическое выделение устройства только по адресу и паролю относятся
к отдельной работе над клиентом.
